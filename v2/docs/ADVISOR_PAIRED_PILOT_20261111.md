## 4. Technical Comparison Against Advisor's `opengrep_triage/benchmark.py` (`P0.1` / `P0.3`)

We inspected `opengrep_triage/benchmark.py`, `opengrep_triage/triage.py`, and `tests/test_pipeline.py` in `_advisor_sources/opengrep-triage.zip` and compared them against `v2/evaluation/score_pilot.py`:

| Dimension | Advisor Reference (`opengrep_triage/benchmark.py`) | NTK Thesis V2 Evaluation (`v2/evaluation/score_pilot.py`) | Impact on Experimental Validity |
|---|---|---|---|
| **1. Granularity of Evaluation Unit** | **Test-Case / File Level (`BenchmarkTestNNNNN`)**: Joins OpenGrep findings by regex `BenchmarkTest(\d{5})` and CWE integer (`t.cwe in r["cwes"]`) against OWASP `expectedresults-1.2.csv`, which has a single file-level boolean (`true`/`false`) per test case. | **Individual Finding / Alert Level (`alert_id`)**: Joins by deterministic Contract 1.1 `alert_id = SHA256(UTF8(scan_sha256 + ":" + finding_index))` + canonical signature `(file_path, start_line, end_line, rule_id, cwe)` and `source_sha256`. | In multi-method files or when a rule flags a benign line inside a vulnerable `BenchmarkTest` file, file-level CSV truth mislabels the individual finding (`truth = "real" if t.is_real else "fake"` at `benchmark.py:203`). Finding-level evaluation scores the exact line and dataflow trace. |
| **2. Decision Policies & Metrics** | Computes test-case `TP, FP, TN, FN`, $\text{TPR} = \frac{\text{TP}}{\text{TP}+\text{FN}}$, $\text{FPR} = \frac{\text{FP}}{\text{FP}+\text{TN}}$, and $\text{Score} = (\text{TPR} - \text{FPR}) \times 100$ across **3 policies**:<br>1. `baseline`: `len(fs) > 0`<br>2. `drop_fp` (Keep Group 1+3): `any(f["verdict"] != "FALSE_POSITIVE")`<br>3. `keep_tp_only` (Keep Group 1 only): `any(f["verdict"] == "TRUE_POSITIVE")` | Evaluates **Arm A (OpenGrep Standalone)** vs. **Arm B (OpenGrep + Qwen)** using fail-safe triage metrics:<br>- `proposed_fp_on_true_fp / labeled_fp`<br>- `erroneously_proposed_fp_on_tp / labeled_tp`<br>- `needs_review_total / total_alerts` (`UNDETERMINED`/`REVIEW` always retained). | Policy 3 (`keep_tp_only`) in `benchmark.py` discards `UNDETERMINED` (Group 3) findings, which risks silently dropping real vulnerabilities when the LLM is uncertain. NTK V2 enforces Policy 2's fail-safe principle (`UNDETERMINED -> REVIEW` is retained) plus mandatory human confirmation. |
| **3. Behavior of `--sample` (`only_scanned=True`)** | In `benchmark.py:126-128`:<br>`if only_scanned: scanned_tests = set(by_test.keys()); tests = {k: v for k, v in tests.items() if k in scanned_tests}`.<br>Only test cases where OpenGrep emitted $\ge 1$ finding are kept in `tests`. | Explicitly separates **per-alert triage evaluation** (on the locked set of $N$ OpenGrep alerts) from **full-corpus scanner detection recall/FPR**. | Under `only_scanned=True` in `benchmark.py`, test cases with $0$ OpenGrep findings ($\text{FN}=0, \text{TN}=0$ for the static scanner) are removed from the denominator. Thus `baseline` trivially yields $\text{TPR}=100\%, \text{FPR}=100\%, \text{Score}=0.0$, which **cannot** be cited as full-corpus detection recall or FPR. |
| **4. Evidence Grounding & Fail-Safe Gates** | `triage.py:114-138` parses free-text `1/2/3` verdicts via regex without JSON schema validation, without `source_sha256` verification, without line/quote existence checks, and without a human confirmation state. | Requires valid JSON (`SUPPORTED`/`REFUTED`/`UNDETERMINED`), 64-hex `source_sha256` match, verified non-comment code line citations in the actual Java file/snapshot, and `human_review_state` (`OPEN` vs. `CONFIRMED_*`). | Prevents hallucinated line numbers, stale file snapshots, or unverified `REFUTED` outputs from being counted as valid FP removals. |
